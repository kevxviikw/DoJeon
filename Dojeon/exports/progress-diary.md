# Progress Diary — PIC Project 1

> **Convention for any session working in this project:** when you make a durable change here — a decision, a pivot, a new doc, a build milestone, an open question resolved — append a short dated entry below (newest date at the top; new entries within today's date append under that date's heading). ## 2026-09-05

- Kunwoo pitched the DoJeon proposal to the club and got feedback back. Four changes came out of it, layered on top of the V3 design:
  1. **Squad-scoped leaderboard** — ranks members within their own 3–6 person squad only, never across squads.
  2. **Solo matching** — a member without a squad can search for potential squad-mates by similarity in goal type/pace, instead of staying solo by default.
  3. **Peer-approved check-ins** — a daily check is no longer confirmed by self-report alone; it's confirmed once at least 75% of the squad approves the submitted evidence (threshold adjustable). Paired with a removal rule: a member is kicked from the squad if missed days exceed one third of the mission's total duration (also adjustable). Solo missions are unaffected.
  4. **Mission-end data collection** — when a mission's duration ends, the squad disbands; with member consent, the app collects achievement/consistency/pattern data at that point as the proposed basis for revenue (a hypothesis, not a finalized model).
- These partially **supersede** two of V3's explicit design decisions: "no leaderboard" (now true only *across* squads, not within one) and "no invented penalties" (the club specifically wanted a real consequence — squad removal — short of anything financial or shame-based).
- Per Kunwoo's instruction, the existing proposal doc's original content was left untouched. A new file, **"DoJeon - PIC Club Proposal (v2, tracked).docx"**, carries the same content with these four updates added as genuine Word tracked changes (visible, colored insertions with change bars) plus a new Addendum section at the end explaining each one and pointing back to the two superseded callouts in Section 6. This is the version headed to the club president.
- **Not yet done:** the Beast Mode Field Manual artifact and the `beast-mode-project-outline.md` doc still describe the pre-feedback V3 design (no leaderboard, no invented penalties, self/AI-labeled evidence trust) and haven't been reconciled with these four changes yet — flagged here so the next session doesn't treat them as current without checking this entry first.
- Built the actual app (backend + non-UI client), under a new `app/` directory alongside these docs. Built to V3 + all four Sept 5 amendments (A-D) above, reconciling this diary's flag. Structure:
  - **Supabase**: full Postgres schema + RLS (`app/supabase/migrations/0001_init.sql`), and one Edge Function per capability — Forge, Push (squad create/join, session start/join/finish, async activity summary), Proof + peer approval, Adjust (evaluate + approval-gated decide), the missed-day removal sweep, the squad-scoped leaderboard, solo matching, and mission-end data collection.
  - **Core engine** (`app/supabase/functions/_shared/logic/`): every business rule as pure, provider-agnostic functions with zero Node/Deno-specific code, so the same files run inside the Edge Functions (Deno) and under Node's test runner. 49 tests passing (`npm test` in `app/`) — this is genuinely verified working, not just written.
  - **iOS client** (`app/ios/DojeonCore`): a dependency-free Swift package — SwiftData models, a Supabase auth/networking layer (Sign in with Apple → Supabase, matching the Field Manual's §04 choice), one service per feature, and `@Observable` view models. Deliberately stops before any SwiftUI view/screen — Kunwoo is designing and building the UI separately. Written carefully but **not compiled**: this session's machine has no Xcode/Swift toolchain, so treat first-build errors in Xcode as expected, not a sign something is fundamentally wrong.
  - Mid-build, swapped the one AI call (Forge's plan decomposition) from Claude to Gemini, specifically to stay on a free tier for longer post-launch — this is a club MVP with no revenue yet. `GEMINI_MODEL` is a required secret with no hardcoded default on purpose: independent lookups while wiring it up returned inconsistent current model names, so the app forces an explicit, current choice at deploy time instead of trusting a guess.
  - One gap flagged for a deliberate decision before shipping squad features: `solo-match`'s current RLS setup doesn't yet support the cross-member read it needs (see the function's own comment and `app/README.md`).
- Did a full launch-readiness review against the proposal + Field Manual + all four addendum items (A-D). **Verdict: not ready to launch, not close.** Every core-loop rule and all four V2 amendments (squad-scoped leaderboard, solo matching, peer-approved check-ins/removal, mission-end consent) are built and pass 49 tests — but that's verified business logic sitting on zero live infrastructure: no Supabase project has ever actually been deployed, no edge function has ever executed once, and the Swift package has never been compiled (no Xcode/Swift toolchain was available while building it, and it isn't even wired into an Xcode App project yet). UI-wise, only 4 of 9+ real screens are even mocked up (Today/Forge/Push/Proof, as a clickable HTML design canvas, not SwiftUI) — Squad, Adjust, mission-end consent, and sign-in have no UI at all. Business-side, the Field Manual's own 6-item approval checklist (§05) has exactly one item done (pitch materials); the app name, Apple enrollment, App Store Connect record, and TestFlight setup are all unstarted, and the president's confirmation of the addendum is still a pending human decision. Also still open: the Field Manual artifact and `beast-mode-project-outline.md` were never updated with amendments A-D (code and this diary are reconciled; those two docs aren't). Next-up order given to Kunwoo: deploy Supabase for real → stand up the Xcode project and fix what doesn't compile → design/build the remaining screens → fix the solo-match RLS gap → then the business checklist.

## 2026-09-02

- Set up this progress diary and the automated daily PDF digest that keeps it as a clean, shareable PDF without anyone needing to type updates by hand.
- State of the project as of today: pivoted from **VoiMo** (a voice-recognition note-taking app) to **Beast Mode**, an extreme-goal planner tied to PIC's "Challenge Everything, Fear Nothing" slogan, built around a **Forge → Proof → Stakes** loop with small accountability pods (3–6 people). VoiMo's plan is shelved, not deleted, and its iOS/Xcode/Swift/AVFoundation/Claude-API groundwork carries over into Beast Mode.
- Open decisions still flagged for Kunwoo: final app name (Apple uniqueness check pending), pod formation model (invite-only vs. auto-matched), real-money vs. symbolic stakes (symbolic for MVP), proof photo/voice privacy disclosure, and backend lock-in (Supabase recommended over CloudKit for multi-user pod queries).
- Beast Mode outline revised twice (V1 → V2 → V3), each round driven by specific calls from Kunwoo. Core loop is now **Forge → Push → Proof → Adjust** (Push replaces the earlier undifferentiated "session" idea; Stakes is dropped as a named stage). Real-money/punitive stakes and any cross-squad leaderboard are ruled out entirely, not deferred — squad presence itself is the motivator (an "eusya-eusya"-style group cheer, i.e. a group challenge of individual goals).
- Push now has a concrete session flow: choose task/output → start a timer → squad can optionally join live (no video call) → submit output or log a blocker → see a squad summary. Async participation is the default since a 3–6 person squad won't always overlap live.
- Solo mode was walked back from "deliberately weaker": it now runs the complete Forge → Push → Proof → Adjust loop with nothing crippled; squad remains the strong recommendation but isn't required.
- Today screen redesigned to lead with next deliverable, milestone progress, deadline status, and next session rather than a streak count. History now distinguishes four event types (not completed, completed-but-unproven, planned rest, session interrupted) instead of one blanket "miss."
- Adjust stage got explicit guardrails so replanning can't quietly postpone the goal: check for recovery room first, only present scope/time/deadline tradeoffs when the goal genuinely no longer fits, require approval, keep both the original and revised commitment visible, and force a full review after repeated Minimum-only days.
- Privacy rules for Proof are now defined rather than open: squad always sees status; the evidence file itself is opt-in per submission; live-session visibility is opt-in per session; leaving a squad or removing evidence can't rewrite the honest historical record.
- Backend choice settled: Supabase (Postgres + Auth), not CloudKit, from the first real feature — needed for multi-user squad queries.
- Full interactive build manual published as an Artifact ("Beast Mode Field Manual"); the superseded V1 manual is kept for reference, not deleted.
- Kunwoo's call at the end of the V3 review: stop expanding the outline and prototype one complete mission loop (Forge → Push → Proof → Adjust, solo) end to end next.
- Remaining open decisions: final app name + App Store Connect uniqueness check (unchanged), squad formation model (invite-only vs. auto-matched), squad size default (keep 3–6 vs. narrow for a first PIC cohort test), and session cadence (fixed shared windows vs. fully flexible per-member scheduling). Solo/proof privacy and backend choice are no longer open — both settled above.
